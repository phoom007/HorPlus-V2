## 2. Dormitory and Account Experience

- Owner ใช้ Google Login สำหรับลงทะเบียนหอพักครั้งแรกจากเมนู `ลงทะเบียน`
- เมื่อมีหอเดียว ให้เข้าหอพักนั้นโดยตรง ไม่แสดงหน้าต่างเลือกหอ
- แสดง Workspace/Dormitory Selector เมื่อมีหอพักแห่งที่ 2 เป็นต้นไป
- การเข้าใช้งานหลังตั้งค่าแล้วให้ผ่าน LINE OA/LIFF ตามสิทธิ์
- LINE OA แยก Credential และ Webhook ต่อหอพัก ไม่มี Shared OA ของ HorPlus
- เชื่อม LINE OA ได้ระหว่าง Onboarding หรือเลื่อนไปเชื่อมเมื่อกดใช้ฟีเจอร์ LINE ครั้งแรก
- ห้ามเผย OA ID, Channel ID, Secret หรือข้อมูลเชื่อมต่อในหน้า Public
- เว็บไซต์สาธารณะ/Directory/SEO ของแต่ละหอพักเป็นงานระยะหลัง ไม่ใช่ Core MVP และห้ามขยายก่อน Core ผ่าน

## 3. Roles and Permission Limit

บทบาทบุคลากรมีเพียง:

1. `OWNER` — เจ้าของ
2. `MANAGER` — ผู้จัดการ
3. `TECH` — ช่างซ่อม/แม่บ้าน

กฎสุดท้าย `A` ยกเลิกคำตอบเดิมที่ว่า Owner ไม่จำกัด:

- บัญชีทุกบทบาทรวมกันสูงสุด **10 บัญชีต่อหอพัก** รวม Owner คนแรก Owner เพิ่มเติม Manager และ Tech
- หนึ่ง User ถือได้เพียงหนึ่งบทบาทต่อหอพัก
- มี Owner มากกว่า 1 คนได้ แต่ต้องอยู่ภายในเพดาน 10
- Owner ทุกคนมีสิทธิ์เท่ากัน
- หาก Owner สูญเสีย LINE เดิม Owner คนอื่นเพิ่ม LINE ใหม่ผ่าน `สิทธิ์และพนักงาน` ได้ หรือติดต่อ Admin HorPlus เพื่อ Recovery
- Recovery ต้องยืนยันตัวตน บันทึกเหตุผล ผู้ดำเนินการ เวลา และ revoke session/binding เดิม

สิทธิ์หลัก:

| ความสามารถ | Owner | Manager | Tech |
|---|---:|---:|---:|
| Dashboard/อาคาร/ห้อง | จัดการ | จัดการ | ดูเฉพาะที่จำเป็น |
| ผู้เช่า/สัญญา | จัดการ | จัดการ | ชื่อ/โทรศัพท์เฉพาะห้องที่มอบหมาย |
| มิเตอร์ | จัดการ | จัดการ | บันทึก/แก้ตามงานที่ได้รับ |
| บิล/เงินสด/โอน/SlipOK | จัดการ | จัดการ | ไม่มีสิทธิ์ |
| อนุมัติผู้เช่า | จัดการ | จัดการ | ไม่มีสิทธิ์ |
| แจ้งซ่อม | จัดการ | จัดการ | จัดการงานที่มอบหมาย |
| ตั้งค่าหอพัก/LINE OA | จัดการ | ดูตามความจำเป็น | ไม่มีสิทธิ์ |

## 4. Building, Room and Price Defaults

- ทุกห้องต้องสังกัด Building
- `roomNumber` ซ้ำได้ต่าง Building แต่ซ้ำใน Building เดียวกันไม่ได้
- ค่าเริ่มต้นไหล `Dormitory → Building → Room`
- Owner แก้ค่าเฉพาะ Building/Room ได้
- เมื่อเปลี่ยนค่า Default ภายหลัง ให้ปรับเฉพาะห้องที่ยังไม่มีสัญญา Active
- Contract ต้องเก็บ Snapshot ค่าเช่า ค่าบริการ มัดจำ กฎงวด และเงื่อนไข ณ เวลาทำสัญญา ห้ามเปลี่ยนย้อนหลังตาม Default
- ข้อมูลอาคาร ห้อง ค่าเช่า และค่าบริการที่กรอกตอนลงทะเบียนต้องถูกนำไปสร้างข้อมูลเริ่มต้น และแก้ภายหลังได้

## 5. Tenant Registration and Contract

- Tenant เข้าและลงทะเบียนผ่านปุ่มถาวรใน LINE OA/LIFF ไม่ใช้ Google Login
- ปุ่มลงทะเบียนใช้ได้จนกว่า Owner จะปิดรับ ไม่ใช่ token เฉพาะคน และไม่มีวันหมดอายุ
- Tenant หนึ่งคนมีคำขอ Active ได้หนึ่งรายการต่อหอพัก
- รองรับทั้ง Owner สร้าง Tenant เอง และ Tenant สมัครผ่าน LINE OA
- Tenant เลือกห้องว่างเอง ระบบต้องตรวจ Availability ที่ Server รวมถึงกรณีจองอนาคตหลังผู้เช่าเดิมย้ายออก
- เอกสารและกฎบังคับกำหนดได้ต่อหอพัก; ถ้าไม่ครบห้ามส่งคำขอ
- Co-tenant บันทึกชื่อและเบอร์โทร ไม่ต้องผูก LINE
- Tenant ต้องเซ็นด้วยนิ้ว/เมาส์บนหน้าจอ พร้อมเก็บเวลา IP, LINE User ID และเวอร์ชันเอกสาร
- Owner Signature ไม่ต้องแนบก่อนขั้นตอนอนุมัติ
- Owner/Manager ทำได้: `อนุมัติ`, `แก้ไข`, `ปฏิเสธ`
- การแก้ข้อมูลโดยผู้อนุมัติต้องแจ้ง Tenant ว่าแก้อะไร; ปฏิเสธต้องมีเหตุผล และ Tenant ส่งใหม่ได้
- อนุมัติแล้ว Tenant เข้าพอร์ทัลได้ทันที
- Invitation สำหรับบุคลากรหมดอายุ 7 วัน ใช้ครั้งเดียว ส่วนปุ่ม Tenant Registration เป็นคนละกลไก

## 6. Term Installments and Deposits

- Owner ตั้งจำนวนงวดสูงสุดของการเช่ารายเทอมต่อหอพัก
- ระบบแบ่งยอดเท่า ๆ กันอัตโนมัติ งวดสุดท้ายปรับเศษสตางค์
- Owner/Manager แก้ยอดและ Due Date ของแต่ละงวดก่อนออกบิลได้ โดยยอดรวมต้องเท่า Snapshot
- มัดจำออกเป็นบิลแยก
- รองรับ `จ่ายมัดจำแล้วก่อนเชื่อม LINE` และ `ให้ Tenant ชำระผ่าน Portal`
- สัญญา Active ได้แม้มัดจำยังไม่จ่าย แต่ต้องแสดงยอดค้างชำระชัดเจน
- ประเภทมัดจำ:
  - `REFUNDABLE`: คืนหลังเลิกเช่า หักค่าเสียหายได้เฉพาะยอดที่จ่ายแล้ว
  - `RENT_CREDIT`: นำยอดที่จ่ายแล้วไปหักค่าเช่าตามกฎของหอพัก
- ห้ามนับมัดจำที่ยังไม่จ่ายเป็นเงินรับหรือเครดิต

## 7. Meter, Bill, Payment and Receipt

- ถึงวันออกบิล ระบบสร้าง `DRAFT` อัตโนมัติ
- Owner/Manager ตรวจและกด `ISSUE`; Tenant เห็นเฉพาะ `ISSUED` เป็นต้นไป
- บิลที่ยังไม่ชำระทำให้เป็นโมฆะได้ ต้องมีเหตุผลและ Audit ห้าม Hard Delete
- หากยังไม่ออกบิล สามารถคืนสถานะในหน้า `จดมิเตอร์` เป็น `ยังไม่ออกบิล` และทำ Draft เดิมเป็นโมฆะ
- บิลที่ชำระแล้วห้ามยกเลิก ต้องใช้ Adjustment/Refund แยก
- Tenant Payment และ Platform Subscription Payment ต้องใช้คนละ Domain/Table/เลขที่เอกสาร
- Owner/Manager Override ผล SlipOK ได้ทั้งคู่ แต่ต้องกรอกเหตุผลทุกครั้ง
- การอนุมัติ Payment ต้อง idempotent และ Receipt ห้ามออกซ้ำ

## 8. Move-out

- วันสิ้นสุดสัญญาเป็นหลัก แต่ Owner/Manager ยืนยันย้ายออกก่อนวันดังกล่าวได้
- ก่อนย้ายออกต้องสร้าง Final Settlement และออก Receipt สุดท้ายตามรายการที่ชำระแล้ว
- เมื่อยืนยัน:
  - ปิด Contract และ Occupancy
  - ยกเลิก Tenant LINE Binding ของหอพักนั้น
  - ห้องเปลี่ยนเป็น `VACANT`
  - Tenant เดิมไม่เข้าดูเอกสารย้อนหลังผ่าน Portal
  - Owner/Manager ยังดูประวัติเดิมตามสิทธิ์
  - Tenant ใหม่เห็นเฉพาะข้อมูลของตน

## 9. LINE Messaging

- Free 30 ครั้ง/เดือน/หอพัก; Paid 300 ครั้ง/เดือน/หอพัก
- Reset วันที่ 1 เวลา 00:00:00 `Asia/Bangkok`
- นับเฉพาะ Push ที่ส่งสำเร็จตามจำนวนผู้รับ: 20 ผู้รับสำเร็จ = 20 ครั้ง
- Reply ไม่นับ
- Failed/Cancelled ห้ามหัก quota; Pending ใช้ reservation ป้องกัน oversubscription
- ข้อความ UI ใช้คำว่า `จำนวนการส่งข้อความ` ไม่ใช้ศัพท์ Push/API quota

## 10. Security and Non-functional

- ทุกคำสั่งต้อง derive Dormitory/Role จาก Session หรือ verified LINE identity ไม่รับจาก Client เป็น authority
- Server คำนวณราคา ยอดเงิน สิทธิ์ จำนวนห้อง quota และ state transition ใหม่เสมอ
- PostgreSQL RLS + transaction-scoped context + application permission guard
- Runtime DB role ห้าม `BYPASSRLS`
- เข้ารหัส Secret, เลขบัญชี, PromptPay และข้อมูลส่วนบุคคลที่อ่อนไหว
- Private object storage + short-lived signed URL + authorization ก่อนออก URL
- Webhook LINE ตรวจ signature, replay, timestamp และ idempotency
- Mutation ทางการเงิน/สิทธิ์/สัญญา/การอนุมัติต้องมี Audit Log แบบ append-only
- เป้าหมายรองรับมากกว่า 10,000 หอพัก โดยเริ่มจากสถาปัตยกรรมต้นทุนต่ำและ scale แยก Web/API/Worker/DB ได้

- ฟีเจอร์ที่เอกสารระบุ `FUTURE` ต้องไม่เป็นเงื่อนไขให้ Core Phase ล่าช้า
